# 4. 版本结束
- UI自动化，覆盖率
- 接口自动化，覆盖率

## 4.1. 为什么要做准入准出

准入准出不是为了增加流程，而是为了在发布前把风险显性化。真正的价值在于：

- 让需求、开发、测试对当前版本的完成度有共同认知。
- 降低“功能做完了但不可发布”的情况。
- 给复盘和质量改进留下可量化依据。

## 4.2. 实际执行建议

- 规则不要太空泛，尽量量化，例如覆盖率、阻塞缺陷数、回归范围。
- 同一团队内要统一标准，避免不同项目口径不一致。
- 每个版本结束后最好沉淀一次准入准出执行情况，反向修正规则。
