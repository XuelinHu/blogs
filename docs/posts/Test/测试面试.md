# 1. 测试理论

- 软件测试的目标是尽早发现风险，并用可复现证据支持修复决策。
- 常见基础包括测试阶段、测试类型、缺陷生命周期、风险优先级和质量度量。

# 2. 业务系统

- 面试中需要能结合业务链路说明测试范围，例如下单、支付、履约、退款等核心流程。
- 重点说明边界条件、异常分支、数据一致性和上下游依赖。

# 3. 测试用例设置

- 用例设计应覆盖正常路径、异常路径、边界值、权限、兼容性和数据准备。
- 复杂业务可以使用等价类、判定表、状态迁移和场景法组合设计。

# 4. 压测结果分析

- 先看吞吐量、响应时间、错误率和资源使用率，再定位瓶颈组件。
- 分析时需要关联应用日志、数据库慢查询、缓存命中率和机器指标。

# 5. 压测场景设计

- 场景设计应匹配真实业务比例，区分基准压测、容量压测、稳定性压测和突发流量压测。
- 明确压测入口、数据隔离、监控指标、停止条件和回滚方案。

## 6. 面试回答建议

- 不要只背概念，要尽量结合一个真实业务场景展开。
- 回答功能测试时，最好带上边界值、异常流和依赖项。
- 回答性能测试时，要说明指标、瓶颈定位方法和优化思路。

## 7. 高频追问方向

- 如何设计支付、下单、库存类测试用例。
- 如何定位线上偶发 Bug。
- 如何推动开发修复高优缺陷。
- 如何评估版本是否可以发布。
